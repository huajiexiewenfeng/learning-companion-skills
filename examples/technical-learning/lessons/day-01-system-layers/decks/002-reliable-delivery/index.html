Lesson deck · Day 01

Day 1｜可靠交付与执行漂移复盘

  1. 可靠交付流：证据到验收的受控路径

    Archive 和当前来源提供输入，Plan 经 Checkpoint 核验后才可写入 Authoritative State，并由 Trace 支撑验收。

  2. Archive、Memory 与 Authoritative State 的三种记录

    Archive 保存可回看的证据，Memory 提供便利但可过期的上下文；只有 Authoritative State 是当前事实，Trace 才说明事实如何变化。

  3. Project Develop Copilot：长对话压缩后的执行漂移

    压缩 Memory 遗漏 active scope 与 Checkpoint 后，代理把候选模块当作当前授权范围并直接修改；回读 Archive、Plan、Authoritative State 与 Trace 才能修复执行漂移。

  4. 误区：完整的 Memory 就是当前事实

    错误。Memory 即使完整也只是压缩上下文；Archive 是历史证据，Plan 是意图，Checkpoint 决定转换，Authoritative State 保存当前事实，Trace 记录实际发生的结果。

  5. 检查问题：恢复后先核对什么？

    恢复长对话后，代理必须核对哪三类信息，才能避免把 Memory 当作 Authoritative State 并造成执行漂移？

  6. 来源与发布门禁

    本课将原始来源、已验证的模型和不可变 HTML 存档分开；每个工件先过离线、响应式和可访问性门禁，再等待桌面与 390px 视觉复核。
